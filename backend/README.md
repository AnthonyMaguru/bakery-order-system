# Backend

REST API used by both the mobile app and the dashboard. Node.js + Express 5 + TypeScript, Prisma ORM on PostgreSQL, Firebase Admin for verifying sign-ins and sending push notifications.

```bash
docker compose up -d     # from the repo root: starts PostgreSQL
cp .env.example .env
npm install
npm run db:migrate       # apply migrations (asks for a name when the schema changed)
npm run db:seed          # two sample bakeries, a cake builder, stock, and a dev staff owner
npm run dev              # http://localhost:4000/api, restarts on save
```

| Script | What it does |
|---|---|
| `npm run dev` | Run with auto-reload |
| `npm run build` / `npm start` | Compile to `dist/` and run it |
| `npm run typecheck` | Type-check without building |
| `npm test` | Run tests (Vitest + Supertest). Add `RUN_DB_TESTS=1` to include the API tests that need a seeded database |
| `npm run db:migrate` | Create/apply a migration after editing `prisma/schema.prisma` |
| `npm run db:studio` | Browse the database in the browser |

## Layout

```
prisma/
├── schema.prisma        Data model: bakeries and everything they own
├── migrations/          Generated by db:migrate, commit these
└── seed.ts
src/
├── config/env.ts        Validated environment variables
├── lib/                 Prisma client, Firebase Admin, push notifications, errors,
│                        bakery access checks, dates in the bakery's timezone
├── middleware/          Auth (requireAuth / optionalAuth), error handler
├── modules/             One folder per resource: routes, validation schemas, service logic
│   ├── bakeries/        Bakery list, settings, staff, blocked dates, capacity calendar
│   ├── builder/         Cake builder option groups and options
│   ├── orders/          Orders, quotes, payments, messages; order-rules.ts has the status rules
│   ├── products/
│   ├── stock/
│   └── users/
├── jobs/                Scheduled jobs (deadline reminders, stretch)
├── app.ts               Express app (imported by tests)
└── server.ts            Starts the HTTP server
tests/
├── rules.test.ts        Business rules, no database needed
└── api.db.test.ts       Whole flows through the API, needs a seeded database
```

Rules that decide things (capacity, builder choices, order statuses, payment status) are plain functions in `availability.ts`, `selection.ts` and `order-rules.ts`, so they can be tested without a database.

## Auth

Clients send a Firebase ID token. `requireAuth` verifies it and creates the user on first sign-in. Staff are users with a `BakeryMember` row for a bakery, as `OWNER` or `STAFF`; owners can add staff from the dashboard (`POST /bakeries/:bakeryId/members`). A platform `ADMIN` can act for every bakery.

Until Firebase is set up, keep `AUTH_DEV_BYPASS=true` and send `x-dev-user: <name>`. Add `x-dev-role: STAFF` to become an owner of the seeded Sweet Crumbs Bakery, or of the bakery named in `x-dev-bakery`:

```bash
curl -H "x-dev-user: dev-staff" -H "x-dev-role: STAFF" http://localhost:4000/api/bakeries/sweet-crumbs/settings
```

See [docs/api.md](../docs/api.md) for every endpoint.
